# Website and survey audit — October 3, 2026

## Scope and release status

Reviewed the public website, signed-in Club Office, survey APIs, PostgreSQL schema,
current records, and operational documentation. The changes in this branch require
review and deployment. Migration 018 must run before the new maintenance handler.
See [operations](operations.md) for the release sequence.

## Corrections

| Area | Problem | Correction |
| --- | --- | --- |
| Custom answers | The literal text “Not answered” was treated as missing; whitespace reached the server as an answer | Validate the value independently of its display text, preserve option zero, and omit optional whitespace |
| Saving | Network and gateway failures could produce technical errors | Preserve answers and retry receipts; require a valid receipt before displaying success |
| Invitations | Closed generic surveys showed the Advisor Studio introduction | Show a neutral unavailable screen and a club contact; hide invalid derived links after signing-secret changes |
| Results | Counts included archived or withdrawn answers; large result lists were unbounded | Count nonempty active responses separately; page officer, shared respondent, and archived results in groups of ten |
| Privacy and queries | Generic survey bootstrap read a full roster to return only the viewer | Select the viewer in SQL; authorize every shared-results page and retain the original Advisor Studio consent rules |
| Event history | Saved RSVP snapshots could make unpublished events appear upcoming | Use current publication state for upcoming counts while retaining historical snapshots |
| Summaries | “Any of these” counted differently in summaries and CSV | Share expansion rules, exclude “None,” “Not sure,” and “Other,” and avoid double counting |
| CSV | Exports silently stopped at 10,000 records | Reject oversized exports explicitly; show a useful message in the office and permit retry |
| Calendar | Loading or failed requests appeared to mean no upcoming events | Distinguish loading, unavailable, and empty calendars; retain fresh article content during event refresh |
| Event details | Missing times and venues were ambiguous | Label them “to be announced” |
| Maintenance | Obsolete survey device tokens accumulated | Delete only expired/revoked tokens, at most 1,000 per run; add indexes matching history and device queries |

## Verification

- All 114 unit/integration tests passed. Coverage includes authorization, CSRF,
  expiry, revocation, preview restrictions, consent, stale revisions, idempotent
  retries, transaction rollback, uploads, exports, and response management.
- The 12 focused survey tests passed again after reducing archived-result pages.
  Active and archived pagination was checked across 23 synthetic respondents.
- Reapplying migration 018 succeeded. Maintenance removed 1,005 obsolete devices
  across two bounded runs, preserved the active device and saved responses, and
  granted no response-deletion permission to the runtime role.
- In-browser survey checks covered create/edit/preview/publish, email verification,
  required questions, literal text, option zero, optional whitespace, consent,
  save/reload, shared results, access removal, and closing.
- A local server saved a submission and dropped the acknowledgement. The UI kept
  the answers; retry returned success with exactly one submission receipt.
- Officer results loaded 10 → 20 → 22 active respondents. The respondent view
  retained the viewer's answer plus all 22 other active responses across pages.
- CSV failure stayed inside Club Office; retry started the download. The closed
  survey screen no longer displayed unrelated advisor instructions.
- At 390 pixels, public events, join, journal, projects, AI Lab, and About fit the
  viewport. Mobile menu navigation, empty membership validation, and AI Lab
  training/reset worked. Survey confirmation was inspected at the same width.
- Hugo built 34 pages without warnings. The backend built successfully. A static
  scan checked 375 local HTML asset/link, CSS URL, and JavaScript import references
  with no missing targets. Installed dependencies reported no audit vulnerabilities.

The existing CI workflow also runs the Club Office browser suite on the pull
request. These checks are functional verification, not a production load benchmark.
The live dataset is small. Paging bounds response size; a concurrently changing
roster can change which responses appear on successive offset-based pages. Refresh
the view to obtain current counts and results.
